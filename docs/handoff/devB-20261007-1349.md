# Dev B Handoff — Access Logs, WebSocket Gate and Telegram Polling

**Date:** 2026-10-07 13:49  
**Status:** Implemented and locally validated with mocks; live Telegram behavior remains unverified.

## Findings and Changes
- `app/core/logging.py`: the PII filter previously replaced `record.msg` with a rendered message and cleared `record.args`. Uvicorn's `AccessFormatter` requires five structured args, causing the reported `ValueError`. Access records now retain their interpolation tuple and mask each string argument.
- `app/api/ws.py`: the consent/config guard previously closed before accepting the socket, which Uvicorn/browser surfaced as HTTP 403 with no useful client message. It now sends an existing `ServerError` frame and then closes; the call still does not proceed without configured settings, consent, and AgentConfig.
- `app/voice/client/caller.js`: microphone permission is deferred until the server sends a call state, so a setup error can be displayed without prompting for a microphone.
- `app/channels/telegram.py`: Telegram request failures now carry only fixed safe categories (`unauthorized`, `forbidden`, `conflict`, `rate_limited`, `server_error`, `timeout`, `connection`, etc.). Polling logs the category, never the bot token, URL, response body, or caller data; it stops retrying persistent authorization/access/conflict failures.
- Regression coverage added/updated in `tests/test_core.py`, `tests/test_telegram.py`, and `tests/test_wizard.py`.
